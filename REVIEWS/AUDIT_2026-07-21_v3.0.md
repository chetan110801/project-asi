# AUDIT — Project ASI content & reader, v3.0

**A cold read of everything in the folder: what is redundant, what is unnecessary, what is too dense, what is stale, and what is missing.**

`Date: 2026-07-21 · Audits: LEARNING v3.0 (35 pages, ~300k words) + INSTRUCTIONS + RESOURCES + the reader (index.html)`
`Method: full structural read + live web freshness pass (HARD_RULES §2.6) · Outcome: drove the reader rebuild + THE_PLAN.md`

> House rule, kept: **truth over comfort.** Two of my own opening hypotheses were wrong and are marked as such below (B3, C1). A review that only confirms its first guess is not a review.

---

## How to read this

Findings are in five buckets, matching the five questions asked: **redundant · unnecessary · too dense · stale · missing.**
Each has a **severity** (🔴 high / 🟡 medium / 🟢 low), a **diagnosis**, and a **fix** — marked `SHIPPED` if it was done in this pass, `QUEUED` if it is written up as a job in [`THE_PLAN.md`](../LEARNING/THE_PLAN.md).

**Headline:** the writing is in far better shape than the scaffolding around it. The 35 learning pages are genuinely strong — grounded, dated, self-critical, and disciplined about not repeating themselves. Almost every problem below is in the *packaging*: metadata leaking into the text, two rival naming systems, a changelog that outgrew its purpose, and a front door that is harder to read than the rooms behind it.

## A. REDUNDANT — the same thing, twice

**A1. 🔴 Two live, incompatible names for the same eleven ideas.**
`INSTRUCTIONS/AGI_ASI_INVESTIGATION_SYSTEM.md` §2 defines the approaches as **P1–P7** (scale, scale+ingredients, neuro-inspired, WBE, neurosymbolic, RL/agents, new paradigm). `RESOURCES/LANDSCAPE.md` then maps every lab onto that P-scheme ("Our path: P1+P2+P6"). But `LEARNING/` — the actual v3.0 spine — uses **AP1–AP11**. The two schemes are not even the same shape: P2 ("scale + new ingredients") silently contains AP3, AP4 and AP5. So following a link from a learning page into `RESOURCES/` drops you into a different vocabulary for the same content, with no conversion table.
→ *Fix `QUEUED`:* pick one — AP1–AP11 — and either remap `LANDSCAPE.md` onto it or retire the P-scheme to `_legacy/`. This is the highest-value single cleanup in the repo, because `LANDSCAPE.md` is the file that answers "who is actually doing this," which the plan leans on.

**A2. 🟡 The map's cards duplicate the modules they point at.**
`APPROACHES_TO_AGI.md` is 16,390 words, most of it eleven ~400-word cards summarising eleven ~7,000-word modules. The duplication is deliberate (map vs. territory) and worth keeping *in principle* — but the cards have grown a running `*SOTA 2026-07 (web):*` commentary that is a second, competing home for facts the module already owns. Two homes means one goes stale silently, and one did (see **D1**).
→ *Fix `QUEUED`:* cards keep only the six fixed fields (Bet · Intelligence is · Optimizes · Strongest critique · Status · → module). All live SOTA commentary moves into the module, which is the one place it can be maintained.

**A3. 🟢 Twelve corpus planning documents describe a campaign that is over.**
`RESOURCES/corpus/` holds `_ACQUISITION_PLAN`, `_CAMPAIGN_PLAN`, `_CORPUS_BUILD`, `_COVERAGE_MAP`, `_LIBRARY_CAMPAIGN_MATRIX`, `_SESSION6_PROMPT`, `_UNIVERSITY_PLAYLISTS` and more — all steering a gathering phase that v3.0 paused. They are inert but they are the first thing a future session reads and mistakes for current instructions.
→ *Fix `QUEUED`:* move to `RESOURCES/corpus/_archive/`, leave one `README` explaining that gathering is paused and why.

## B. UNNECESSARY — things that cost more than they return

**B1. 🔴 Machine metadata was being printed as body text on 32 of 35 pages. `SHIPPED`**
Every module opens with YAML frontmatter (`id: c-ap1-scale`, `sortkey: 2001`, `domains: [...]`, `provides: [...]`). `build_site.py` never stripped it, and Python-Markdown does not handle frontmatter natively — so it rendered as a horizontal rule followed by a paragraph of database fields, *above the title*, on every page but three. That is the single most visible defect in the whole project and it had been shipping since the reader was built.
→ *Fix `SHIPPED`:* `split_frontmatter()` in `build_site.py` now parses it out and reuses it (reading-time estimates on the new home page come from it). Verified: `grep -c 'sortkey:' index.html` → **0**, was 32.

**B2. 🟡 `WHATS_NEW.md` (20,108 words) now costs more than it returns.**
It is the third-largest file in the project — 6.7% of the entire corpus — and it exists to solve one problem, stated in its own first line: *"So you never re-read what you've already read."* Two things have undercut it. First, it says outright that "the exact, line-by-line record is in git" — so it is a hand-maintained duplicate of `git log`. Second, and decisively: **the new home page now tracks read/unread state per page automatically**, with a progress bar on every entry and a "continue where you left off" card. The job the file was written to do is now done by the reader, for free, without anyone maintaining it.
→ *Fix `QUEUED`:* keep the newest ~15 entries as a "what changed recently" note; move the rest to `RESOURCES/_archive/CHANGELOG.md` so it stops appearing in the reader as a peer of the study material.

**B3. 🟢 The `INSTRUCTIONS/` layer is mostly superseded — but less than it looks. *(hypothesis partly wrong)***
My opening guess was that all 20 files (~27k words) were dead v1.0–v2.6 scaffolding. Reading them, that is too harsh: `HARD_RULES.md` is live and binding (its §2.6 freshness rule is what caught **D1**), and `PRINCIPLES` / `LEARNING_METHOD` / `RESEARCH_METHOD` still govern how pages get written. What *is* dead weight: `VERSION_HISTORY.md` (7,470 words of changelog — same problem as B2), and the process-design documents for workflows the project no longer runs (`DOMAIN_DISCOVERY_SYSTEM`, `MILESTONE_AND_SHOWCASE_SYSTEM`, `KNOWLEDGE_PROCESSING_SYSTEM`, `RESOURCE_COLLECTION_SYSTEM`).
→ *Fix `QUEUED`:* keep four, archive the rest. Do not archive `HARD_RULES.md`.

## C. TOO DENSE — things that should be broken down

**C1. 🔴 The front door is the hardest page to read. *(this is the one that matters)***
Each of the eleven cards in `APPROACHES_TO_AGI.md` is a **single ~400-word paragraph carrying eight or more labelled fields** — *Bet · Intelligence is · Optimizes · Strongest critique · Grounding · SOTA · the honest novelty gap · Deep-dive written · Pulls in.* See lines 97–107. The information is excellent; the delivery is a wall. And this is the *first* page anyone opens: the map that is supposed to make eleven ideas comparable at a glance is the one place where they cannot be compared at a glance, because each is a block of prose you must read linearly to extract five fields from.
→ *Fix `QUEUED`, highest priority in the content queue:* one card = one small structured block (the reader already renders tables and definition lists cleanly). The point of a card is that the eye can jump straight to "Strongest critique" across all eleven. Right now it cannot.

**C2. 🟡 There is no short rung anywhere on the staircase.**
The shortest page is 2,255 words; the median module is ~8,000; six pages exceed 10,000. There is no 3-minute re-entry point for someone coming back after a week. The template already has the right tool — an **"In one minute"** opener — but it is present on only **16 of 35** pages.
→ *Fix `QUEUED`:* make "In one minute" universal and add it to the final gate in `HARD_RULES` §7.

**C3. 🟢 The shared template is applied unevenly.**
Across 35 pages: "You are here" 34, "How to use this" 33, "Connections" 33, "Revision notes" 33, "Honesty box" 32, "Check yourself" 32, "Where the facts come from" 31, "In one minute" 16. The gaps are not deliberate — they are drift.
→ *Fix `QUEUED`:* a five-line checker script in the build; fail loudly rather than drift quietly.

## D. STALE — the live freshness pass (web, 2026-07-21)

**D1. 🔴 The load-bearing ARC-AGI-2 number is six months out of date — and the *argument* built on it needs restating, not just renumbering.**

What the corpus says now:
- `APPROACHES_TO_AGI.md:99` (AP2 card): *"on the harder ARC-AGI-2 (built to resist memory), the best pure reasoning model reached only ~37.6% (Opus 4.5, Dec 2025, ARC Prize)"* — and uses it to argue the novelty gap is real.
- `20-the-approaches/08_ap8-program-synthesis-arc.md:25`: *"ARC-AGI-2 (2025, best verified frontier ~37.6%)"*.

What is true as of 2026-07-21. **ARC-AGI-2 now has two numbers, 3.5× apart, and which one you quote decides the argument:**

| Track | Constraint | Current best | Reading |
|---|---|---|---|
| Frontier-API public board | run may cost up to **$10,000** | **GPT-5.5 — 85%** (GPT-5.4 Pro 83.3%, Gemini 3.1 Pro 77.1%) | **above** the ~60% human test-panel average |
| ARC Prize Kaggle track | no internet, **~$50/submission**, held-out private set | **24.03%** at **$0.20/task** (NVARC) | nowhere near solved |

So the corpus's 37.6% is a *third* thing again — Claude Opus 4.5 in thinking mode at $2.20/task — and it is no longer the frontier.

The important part is not the number. It is that **the novelty gap did not close; it moved.** ARC Prize's own conclusion from the 2025 competition: *"The accuracy gap is now primarily bottlenecked by engineering while the efficiency gap remains bottlenecked by science and ideas."* The corpus currently uses ARC-AGI-2 as its strongest single piece of evidence against AP1/AP2 and for AP8. That evidence now has to be re-stated on the efficiency axis, or a careful reader who checks the leaderboard will conclude the corpus is simply wrong.

→ *Fix `QUEUED`, top of the content queue:* update the two card/module lines; replace "the best model only gets 37.6%" with the two-track table above; carry the "accuracy = engineering, efficiency = science" line into the verdict, where it sharpens rather than weakens the argument.

**D2. 🟡 Missing: the one ARC-AGI-3 number that matters most for a solo researcher.**
Credit where due — `50-deep-dives/03_ap8-deep-dive-the-research-frontier.md` already covers ARC-AGI-3 well (the 25 March 2026 launch, "no instructions, no rules, no stated goals," the explore→model→goal→plan ladder, and frontier AI at ~0.5% vs humans at 100%). All still accurate. What it does not have: the **best purpose-built agent scores ~12.6%** — roughly **34× better than the best frontier model** (Gemini 3.1 Pro, 0.37%). That single comparison is the strongest evidence in the entire project that a person with ideas and no datacentre can currently beat a frontier lab on an open, unsaturated benchmark.
→ *Fix `QUEUED`:* add to the AP8 frontier deep dive and, more importantly, to the new "way in" page.

**D3. 🟢 Missing: the Tiny Recursion Model.**
`TRM` (Jolicoeur-Martineau, Samsung SAIL Montréal, arXiv 2510.04871): a **7-million-parameter, 2-layer** network scoring **45% on ARC-AGI-1 and 8% on ARC-AGI-2**, beating DeepSeek R1, o3-mini and Gemini 2.5 Pro with **under 0.01%** of their parameters — by recursing on its own answer up to 16 times instead of being big. The corpus mentions test-time training and NVARC's use of TRM components, but never the result itself.
→ *Fix `QUEUED`:* this is the single most motivating data point for a zero-budget learner and belongs in AP8 and in the plan.

> ⚠️ *Sourcing note, per the project's own staleness rule:* the 85% figure comes from leaderboard aggregators (llm-stats.com, benchlm.ai) that agree with each other and with ARC Prize's documented "$10,000 per run" display cap. The Kaggle-track figures come from ARC Prize's own 2025 results analysis. Re-verify the 85% against `arcprize.org/leaderboard` directly before it is written into a module.

## E. MISSING — the gap that actually blocks the stated goal

**E1. 🔴 The project teaches you to *judge* the eleven bets. It does not yet teach you to *work* on one. *(hypothesis partly wrong — see below)***

Every module states its own scope plainly: *"This page is not a how-to guide. It is a way to judge the idea."* That was exactly right for the mapping phase, and the mapping phase is done. But the stated goal is to eventually work on one of these problems, and nothing in the 35 pages answers: *what does an experiment in this approach look like? what would I actually run? what is the smallest real contribution? which open problem could I attack this month?*

I have to correct my own first draft here. I initially wrote that this was missing entirely. It is not. `50-deep-dives/03_ap8-deep-dive-the-research-frontier.md` Part 3 does the job properly — it explains that the ARC Prize's cost cap **forbids** the expensive road, that the top prize requires open-sourcing inside a fixed Kaggle compute budget, and it says outright: *"the efficiency track is **winnable without a giant tech company's compute**"* — citing LPN at ~10% on 40M parameters and CompressARC running on a single gaming GPU.

So the way in exists. The problem is **where** it exists: three paragraphs inside the sixteenth of sixteen optional deep dives, under one approach, framed as an aside. The most actionable content in the project is also its most buried.
→ *Fix `SHIPPED` (first version):* promoted to a first-class page — [`THE_PLAN.md`](../LEARNING/THE_PLAN.md) — with the live competition deadlines, free-compute reality, and the efficiency-frontier argument generalised beyond AP8.

**E2. 🔴 The open-questions ledger is an empty container.**
`INSTRUCTIONS/OPEN_QUESTIONS_SYSTEM.md` is a careful 706-word specification of *how to record* an open question — the fields, the confidence tags, the prized "dissolved" outcome. It contains **zero actual questions**. The system for the thing exists; the thing does not. Meanwhile the 35 learning pages are full of well-posed open questions, each sitting inside an "Honesty box" or a "Stuck #N" section where nothing can be done with them.
→ *Fix `QUEUED`, highest leverage in the whole audit:* harvest every "Stuck #N" and Honesty-box admission across all 35 pages into one ranked ledger, tagged by *what it would take to attack it* — read / reproduce / experiment / needs-a-lab. That single file converts a library into a research agenda, and it can be built entirely from material already written.

**E3. 🟡 No map of people, venues, or how work gets seen.**
`RESOURCES/LANDSCAPE.md` maps labs, bets and valuations. It does not map the things that matter to someone trying to enter: who to read, where the argument actually happens, which workshops take outsiders, which programmes exist for people with no institutional affiliation (EleutherAI's SOAR takes applicants with *no* prior research experience), and where open contribution is genuinely wanted (Prime Intellect's open RL-environment hub).
→ *Fix `QUEUED`:* a "who and where" companion to LANDSCAPE.

**What is genuinely good and should not be touched:** the zero-repetition discipline holds under test — concepts are cross-referenced, not re-explained, across 23 files. The prose is plain without being shallow. Every page carries an Honesty box that argues against itself. The dating and sourcing habit is what made the freshness pass possible at all. **The problem is never the writing. It is that the writing is wrapped in scaffolding from three earlier versions of the project.**

**The one-line verdict:** stop adding pages; spend the next passes on the front door (C1), the stale argument (D1), and the open-questions ledger (E2). The library is built. What is missing is the index of what is still unknown.
